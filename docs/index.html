Volatility Scanner

A live options dashboard: it inverts every quote to an implied volatility, fits a smile per expiry and runs five no-arbitrage checks, twice a second.

Implied volatility

The solver recovers volatility wherever the price depends on it#

Implied volatility is the σ that makes the Black–Scholes price equal the quoted price; there is no closed form, so it is found by root-finding. The solver first rejects prices outside the no-arbitrage bounds, starts Newton's method from the Brenner–Subrahmanyam guess, and hands any contract whose step leaves the bracket or whose vega is too flat to Brent's method — 21% of this set.

Every contract with usable vega solved. The largest error is the same order as the stopping rule — Newton ends once a step moves σ by less than 10⁻¹² — and the median, 2.2 × 10⁻¹⁶, is double-precision rounding.[E1]

Below the cutoff the price carries almost no information about σ. Of the 400 such contracts, 331 still returned a value, with errors up to 0.28 in σ: a root that reproduces the price, but not the volatility that set it. The cutoff is applied in tests and in this measurement; the dashboard does not flag these quotes.

Smile fit

SVI recovers its simulated smile to the noise floor#

SVI (stochastic volatility inspired) describes one expiry's smile with five parameters for total variance σ²T as a function of log-moneyness. Each expiry is fit separately, weighted by vega, and the fit is checked for butterfly arbitrage through its density.

The test is close to circular, and the report treats it that way. The simulated chain is generated from SVI curves plus independent N(0, 0.0002) noise in each quote's volatility, so an SVI fit can at best recover that curve to the 0.02-point noise. In-sample RMSE of 0.017–0.032 vol points means the fitter recovers its own model; it says nothing about how SVI fits real quotes.[E4]

The 7-day expiry is the exception: its held-out error is 5.7× the noise. That slice has the sharpest smile in the simulator, and each held-out score rests on 7 quotes; which of the two drives the gap is not tested.

Arbitrage checks

Five no-arbitrage checks stay quiet on clean quotes and fire as noise grows#

A static arbitrage is a set of prices that lets a fixed portfolio of options lock in a profit. Each tick, the scanner tests 361 conditions across the chain. Every violation is sized in dollars per option and, when the chain has bid and ask quotes, compared with the cost of crossing half the spread on every leg.[E5]

The five static no-arbitrage checks
CheckWhat it requires
monotonicityCall prices fall as strike rises
a higher strike can never be worth more
slopeCall prices fall no faster than the discounted strike gap
C(K₁) − C(K₂) ≤ e^(−rT)(K₂ − K₁)
butterflyPrices are convex in strike
the middle of three strikes sits on or below the chord
put_call_parityCalls and puts agree
C − P = e^(−rT)(F − K) at every shared strike
calendarTotal variance grows with expiry
σ²T at a fixed log-moneyness never falls with T

At the simulator's default noise (0.02 vol points) no check fires. Raising the noise produces violations at a rate that grows with it — consistent with the checks catching the price inconsistencies noise creates. The sweep does not separate which check fires; no real chain has been archived to test against.

Streaming

A slow browser skips to the newest tick instead of slowing the rest#

One producer task builds a tick every 0.5 s — solve, fit, check — and serializes it once. Each WebSocket client gets an asyncio.Queue(maxsize=1). Publishing never waits: if a client's slot still holds an unsent tick, that tick is dropped and the new one takes its place.[E8]

def publish(text):
    """Queue text for every client without waiting on any of them."""
    for outbox in clients.values():
        if outbox.full():
            outbox.get_nowait()  # drop the stale tick the client has not sent yet
        outbox.put_nowait(text)

A test stalls one fake socket mid-send and checks that a second socket keeps receiving ticks, and that the stalled one, once released, receives the newest tick rather than the backlog. A second test drops a client that disconnects mid-send.

Limitations

Every result here comes from simulated quotes#

  • Simulated data only. No result here comes from market quotes; the real-data mode (yfinance) is untested in this report.
  • The fit test is near-circular. The chain is generated from SVI, so fit error measures recovery of the generating curve, not SVI's fit to real smiles.
  • Low-vega quotes are not flagged. Below vega 10⁻⁴ × spot a returned σ can be off by up to 0.28; the dashboard shows it like any other.
  • European pricing. Black–Scholes assumes European exercise; listed SPY options are American, so their implied volatilities are approximate.
  • One seed. Accuracy and fit come from seed 7 only; the sweep across noise levels reuses it.
  • Shared machine for timing. Load average 4.95 / 6.50 / 6.76 at the start; the 1.47× ratio is indicative.

Reproduce

Reproduce it in five commands#

Commands run from a clone of allenwang0/volatilityscanner.

  1. Install (Python 3.11 or 3.12) and run the tests.

    make setup PYTHON=python3.12
.venv/bin/pytest

  2. Recompute the accuracy, fit and arbitrage results and the portfolio card (a few seconds).

    .venv/bin/python report.py --seed 7 --card site/card.json

  3. Re-run the timing benchmark (about a minute).

    .venv/bin/python -m bench.bench_iv --json results/bench_iv.json

  4. Rebuild this page and the README Highlights from the result files.

    python3 scripts/build_report.py --readme README.md

  5. Run the dashboard and open http://127.0.0.1:8000.

    .venv/bin/python main.py --seed 7

report.py prints “round trip max error 2.5e-12” and one RMSE line per expiry; git diff results stays empty except for timings.
